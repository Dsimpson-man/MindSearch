# MindSearch 产品与设计评审

> 评审对象：MindSearch v2.1.1（工程名 `JumpSearch`）
> 评审范围：`ContentView` / `OnboardingView` / `SettingsView` / `Destinations` / `UIKitTextField` / `VoiceInput` / Widget
> 说明：评审期间没有 macOS 构建环境，所有结论来自源码阅读；标注「待真机」的条目需要在设备上复核。

---

## 0. 定位判断

这不是一个「搜索工具」，是一个**「少一步」的工具**。它的竞品不是搜索引擎，是用户手指的肌肉记忆。

三层价值：

- **功能层**：把 query 送到 24 个 App 的搜索页。
- **行为层**：把「打开 App → 找搜索框 → 输入」压成「说一句 → 回车」。
- **情绪层**：v2.0 的纸感与留白，让它不像工具，像一张便签。

关键判断：**功能层没有护城河**（URL scheme 是公开的，谁都能做），真正的资产是行为层养成的习惯。任何增加步骤、增加犹豫的改动，都是在拆自己的墙。

## 1. 产品层

### 1.1 三类用户，三种诉求

| 用户 | 场景 | 真正想要的 | 现在的卡点 |
| --- | --- | --- | --- |
| 单平台重度 | 一天十几次小红书 / 抖音 | 零思考 | 应用槽每次都得打，或依赖默认 APP |
| 跨平台查证 | 一次连搜三四个平台 | 快速换目标 | 换应用要重新打字 |
| 记录型 | 想到就存 | 不打断思路 | 存想法是隐式规则，事前看不见 |

### 1.2 四个结构性问题

1. **隐式规则过载。** 目前有五条「没人告诉你」的规则：回车双义、长按输入框说话、长按别名改 URL、再点 tab 回搜索、超阈值才出现的提示。一个 App 有五条潜规则，等于没有规则。
2. **能力不可见。** 支持 24 个目标，新用户从界面上看到的是 0 个；引导页给了 4 个首字母就结束了。
3. **闭环断裂。** 剪贴板模式（7 个目标）、小组件二次跳转、网页兜底弹窗——三处都是「做到了但没做完」。
4. **失败无梯度。** 所有错误都是同一句 1.6 秒的 toast，用户来不及读，也不知道下一步该干嘛。

### 1.3 四条设计原则

建议写进 README，作为后续所有改动的判据：

1. **一屏一动作** —— 每个界面只承担一个主动作。
2. **结果前置** —— 按下之前就知道会发生什么。
3. **能力可发现** —— 至少让用户看见存在什么。
4. **失败可逆** —— 破坏性操作必须能撤回。

### 1.4 优先级矩阵

| 级别 | 项 | 性质 |
| --- | --- | --- |
| P0 | 左滑删除实际失效 | 缺陷 |
| P0 | 长按说话与文本选择冲突 | 缺陷 |
| P0 | 回车双义且不可见 | 设计缺陷 |
| P0 | 清空记录无确认 | 缺陷 |
| P0 | `db` 别名冲突（豆瓣吃掉豆包） | 缺陷 |
| P1 | 应用槽召回压力 | 设计 |
| P1 | 回搜索的隐藏手势 | 设计 |
| P1 | 剪贴板目标降级 | 策略 |
| P1 | 闲鱼 scheme 更新 | 配置 |
| P2 | 引导不可重看 | 设计 |
| P2 | 死代码 + 过期截图 | 卫生 |
| P2 | 可访问性四项 | 合规 |

### 1.5 可本地埋点（无后端）

搜索发起数、成功跳转数、网页兜底数、没装 App 数、没找到应用数、改判数、想法保存数、从记录再搜数。

唯一该盯的指标：**一次成功率 = 成功跳转 ÷ 发起**。低于 90% 说明深链在烂，或者用户根本不知道该打什么。

## 2. 设计层

### 2.1 交互模型评估

| 元素 | 判断 | 备注 |
| --- | --- | --- |
| 一句话语法 `用 X 搜索 Y` | 好 | 罕见的「可以朗读出来」的界面 |
| 幽灵补全 | 好，但弱 | 只给一个候选、只做前缀匹配 |
| 呼吸主按钮 | 想法好，执行有问题 | 见 2.5 |
| 没有选择页 | 最大的赌注 | 也是最大的召回压力 |
| 两个 tab | 结构对 | 但回退路径不可见 |

### 2.2 五条隐藏手势的处理

| 手势 | 是否唯一入口 | 建议 |
| --- | --- | --- |
| 长按关键词框 = 说话 | 否（有麦克风按钮） | 让位给文本选择，只保留麦克风按钮 |
| 长按别名 = 改 URL | 是 | 改成行尾 chevron 显式入口 |
| 再点当前 tab = 回搜索 | 否（有 ‹ 搜索） | 加视觉暗示即可 |
| 超阈值自动存想法 | 是 | **必须可见化** |
| 应用槽无长按 | — | 可新增「长按出应用面板」作为召回补充 |

### 2.3 信息架构

搜索常驻 + 两个 tab 的结构是对的，不建议动。问题在于「搜索」是根页面却没有 tab 身份，导致回退路径只能靠记忆。两件小事即可缓解：

- 选中态的 3pt 圆点改成 6pt 短横，强化「当前位置」暗示；
- 从列表返回时给搜索页一个极轻的 0.3s 淡入，让「回来」这件事有落点。

### 2.4 反馈系统

现状是单行 toast、1.6 秒、无图标、无撤销。建议分三级：

| 级别 | 形态 | 时长 | 例子 |
| --- | --- | --- | --- |
| 提示 | 底部胶囊，无操作 | 1.6s | 已存为想法 |
| 需要决定 | 胶囊 + 一个动作 | 5s | 已存为想法 · **搜索** |
| 破坏性 | 胶囊 + **撤销** | 5s | 已清空 12 条 · **撤销** |

### 2.5 视觉系统

方向是对的：暖雾白 `#F4F1EA` + 炭墨 `#3A3630` + 雾绿 `#6B7A6A`，衬线标题配等宽正文，像纸质索引卡。四个具体问题：

1. **等宽字承担了太多正文。** 9–13pt 的 mono 大量用于说明、分组标题、计数，视觉上全部降级成「注释」。建议 mono 只留给数字、计数、URL、状态；说明文字回到 13–14pt 的常规字重。
2. **对比度不够。** `faded = ink 42%`，暖雾白底上约 2.3:1。建议提到 0.55–0.62，或规定 42% 只用于 ≥14pt 的装饰性文字。
3. **呼吸圆是唯一的持续运动。** 3.4 秒无限循环，在一个「安静」的界面里反而最吵，也费电。建议改成：待机时 6 秒一次、幅度减半；一旦有任何输入就停。
4. **深色模式的纸纹失效。** `multiply` 混暖黑等于没有纹理。深色下改用 `.overlay` + 低透明度亮噪点。

### 2.6 动效

0.45–0.9s 统一，方向对。缺两点：

- 没有读 `accessibilityReduceMotion`；
- 进和出一样快，建议出场压缩到入场的 70%（0.6s 进 / 0.42s 出）。

### 2.7 可访问性清单

| 项 | 现状 | 改法 |
| --- | --- | --- |
| Dynamic Type | 全部固定字号 | `.custom(size:relativeTo:)` + `@ScaledMetric` |
| 对比度 | faded 2.3:1 | 提到 0.55 以上 |
| 触控目标 | ghost 文本、3pt 圆点 | 至少 44×44 命中区 |
| VoiceOver | 主按钮写死「搜索或存为想法」 | 随当前动作变 |
| 减弱动态 | 未处理 | 呼吸、面板升起、列表转场全部降级 |

## 4. 落地方案

### 4.1 回车语义（P0，本次确定的方案）

问题：`text.count > ideaThreshold` 是唯一裁判，但它藏在代码里；提示只在判完之后才出现，且不能改判。

三条原则：结果可见、可改判、不新增主按钮。

| 状态 | 右侧提示 | 回车行为 | 主按钮图标 |
| --- | --- | --- | --- |
| 未超阈值 | 不显示 | 搜索 | `arrow.right` |
| 超阈值 · 默认 | `25 字 · 回车存为想法`（可点） | 存想法 | `bookmark` |
| 超阈值 · 已改判 | `25 字 · 回车直接搜索`（雾绿） | 搜索 | `arrow.right` |

配套规则：

- 键盘 `returnKeyType` 跟随切换（`.search` ↔ `.done`），不能嘴上说存、键上写搜；
- 模式是一次性的：执行一次后重置，文本降回阈值以下也重置；
- 阈值判定保持 `>`，提示文案必须与判定严格一致；
- 中文组词期间（`isComposing == true`）冻结提示与按钮状态，上屏后再算；
- 短文本想存想法：长按主按钮 0.4s（补充路径，不是唯一路径）；
- 「换个应用」面板里的关键词永远走搜索，不继承这个模式。

### 4.2 应用槽召回（P1）

- 空槽时在细线下方淡出 3–4 个最近应用，点一下填入；
- 幽灵补全支持多候选（打 `d` 现在只能得到豆瓣，抖音、大众点评、豆包、DeepSeek 全被吃掉）；
- 长按应用槽可唤出完整应用面板（补充入口，不替代打字）。

### 4.3 列表删除（P0）

换成 `List`（`.listStyle(.plain)` + `.listRowSeparator(.hidden)` + 自绘行背景），或自己写拖拽手势。不要保留一个「看起来有、实际没有」的交互。

### 4.4 剪贴板模式（P1）

闲鱼已可直连，去掉剪贴板。其余 AI 目标建议降级：优先网页兜底，只在用户手动改过 URL 时才走剪贴板。理由是这个模式要求「跳过去 → 长按 → 粘贴 → 允许粘贴」四步，是整个 App 里最割裂的一段。

### 4.5 别名冲突（P0）

`db` 同时是豆瓣和豆包的首字母。建议：同前缀多命中时，幽灵预览显示第一个并在右侧标 `+2`，点一下循环候选；或在 `searchKeys` 里去掉豆包的 `db`（豆包用 `doubao` / `db` 二选一）。

### 4.6 清空记录（P0）

加二次确认，或改成可撤销的 5 秒胶囊。
